# WC26 Matchday Intelligence

Live AI-powered analysis platform for the 2026 FIFA World Cup. Every fixture, every result, every player — with real-time data and AI that explains what's happening and why it matters.

**[wc26-matchday.vercel.app](https://wc26-matchday.vercel.app)**

---

## What it does

- **Live scores & match reports** — Results, goalscorers, cards and substitutions pulled live from ESPN's public API with no API key or quota
- **AI match reports** — Full-text narrative match reports generated by GPT-4o from structured event data (scorers, minutes, cards, possession stats)
- **Streaming AI analyst** — A tournament-aware chatbot that answers questions about scores, players, form and fixtures using live context injected at request time
- **"Catch me up" briefing** — One-click plain-English summary of the entire tournament written for someone with zero football knowledge
- **Starting lineups on the pitch** — Official formations rendered visually, updated ~60 min before kickoff
- **Player profiles** — Career stats, club history, and World Cup record for every player in the squad
- **Tournament leaders** — Live top scorers, top assisters, clean sheet leaders, and discipline table
- **Group standings & bracket** — Final group table and full knockout bracket updating as results come in

## AI architecture

Three distinct AI integration patterns are demonstrated:

**1. Streaming chat with injected context (RAG-lite)**
`/app/api/chat/route.js` — The system prompt is built at request time by fetching live tournament data (top scorers, knockout results, R16 fixtures, all 32 teams). This context is injected before every conversation turn so the model always has current information without fine-tuning. Responses stream token-by-token to the client via `ReadableStream`.

**2. Structured-data-to-prose generation**
`/app/api/report/route.js` — ESPN returns structured event data (goal minutes, scorers, card types, possession percentages). This is converted into a natural-language prompt that asks the model to write a journalist-quality match report. The output is cached with a 24-hour `Cache-Control` header since finished matches don't change.

**3. Audience-aware summarisation**
`/app/api/catchup/route.js` — Generates a plain-English tournament briefing for users with no sports background, using current scorer data as grounding. The prompt explicitly instructs the model to explain any jargon and write for a general audience.

## Data pipeline

```
ESPN Public API
    │
    ├── /scoreboard?dates=YYYYMMDD   →  live scores, status, events
    ├── /summary?event={id}          →  lineups, player stats, formations
    ├── /competitors/{id}/roster     →  squad lists
    └── /statistics                  →  tournament leaders (aggregated across all matches)
         │
         ▼
    Next.js API routes (server-side)
         │
         ├── /api/scores     →  scoreboard for a date
         ├── /api/result     →  full match result + events
         ├── /api/leaders    →  tournament top scorers / assists / keepers
         ├── /api/lineups    →  starting XI + formations
         ├── /api/standings  →  group table
         └── /api/chat       →  streaming AI with live context
              │
              ▼
         React client (Next.js App Router, 'use client')
```

All ESPN calls go through a server-side cache layer with configurable TTLs — 30s for live matches, 1h for completed ones — so the client never hits ESPN directly and the app stays within Vercel's free tier.

## Running locally

```bash
git clone https://github.com/ovais-yusuf/wc26-matchday.git
cd wc26-matchday
npm install
```

Create `.env.local`:
```
OPENAI_API_KEY=sk-...
```

```bash
npm run dev
# → http://localhost:3000
```

The app works without an API key — all ESPN data loads normally. AI features (chat, match reports, catch me up) show a graceful error until a key is provided.

## Design decisions

**No external CSS framework** — the entire UI is hand-written CSS with custom properties. Dark/light theme switching is implemented via a `data-theme` attribute on `<html>` with CSS variable overrides, persisted to `localStorage`.

**No database** — fixture data, editorial content, and team profiles live in `staticData.js` and `editorial.js`. Live data comes from ESPN at request time. This keeps the deployment completely serverless with zero infrastructure cost.

**Streaming over request/response** — all three AI endpoints use streaming so users see text appearing in real time rather than waiting for a complete response. Implemented via `ReadableStream` in Next.js App Router API routes.

**Client-side leaders pre-fetch** — the AI chat receives tournament leaders data from the client (pre-fetched on page load) rather than fetching it server-side. `getLeaders()` aggregates 80+ individual ESPN match summaries — too slow for a serverless cold start. Separating the fetch path solves the latency problem without caching infrastructure.
